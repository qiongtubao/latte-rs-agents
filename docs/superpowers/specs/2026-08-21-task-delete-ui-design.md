# 任务删除 UI 设计

## 目标
在任务看板详情抽屉为任务和子任务提供删除按钮，并将删除后的任务归档到 `.latte/tasks/archive/`。

## 行为
- 所有任务详情抽屉显示危险样式“删除任务”按钮。
- 点击后使用浏览器二次确认；取消不发请求。
- 子任务可以单独删除，成功后从看板消失并归档。
- 有子任务的父任务禁止删除，服务端返回明确错误；子任务必须先处理。
- 无子任务的父任务可删除并归档。
- 删除成功后刷新任务列表并关闭当前详情抽屉。
- 删除失败保留抽屉和任务，使用已有 toast 显示错误。
- 不做级联删除，不把子任务提升为根任务。

## 实现边界
- 复用已有 `deleteTask()` API 和 `DELETE /api/tasks/:id` 接口。
- 前端把 `delete` 加入状态动作映射，抽屉即可统一渲染任务/子任务按钮。
- 后端在从内存移除前检查 `children_of(id)`，避免产生孤儿子任务。

## 验证
- UI 单元测试覆盖 delete action 映射和 API 请求映射。
- Rust 单元测试覆盖删除叶子任务归档、父任务有子任务时拒绝且父子文件保持不变。
- 运行前端相关 Vitest 与 Rust `cargo test` 任务存储测试。
