<instruction>
- 读**代码**文件（.c/.h/.cpp/.rs/.go/.py/.ts/.js/.java）且不带行范围时，`read` **默认回传结构摘要**：只列顶层定义的签名 + 行号，函数体折叠成 `… N ln elided (start-end)`。（代码走 code-graph）
- 读**文档**（.md/.markdown/.mdx/.txt）且不带行范围时，`read` **默认回传大纲**：只列各级标题 + 行号，正文折叠。（文档走 doc-graph 式大纲）
- 两种情况你都**不需要**特意换别的工具——直接 `read` 就自动拿到「地图/目录」，省 token。
- 要看某段**完整内容**：按摘要/大纲里的行号重读，例如 `read path:120-160`（footer 有现成示例）。
- 要**整文件原文**（含折叠部分）：`read path:raw`。
- 已知确切行号：`read path:start-end` / `path:start+count`。
- **一次读多个文件**：把路径放进 `paths` 数组，一次最多 10 个——
  `{"paths": ["src/a.c:20-80", "include/b.h", "src/c.c:raw"]}`。
  每项支持与单文件相同的选择器，按输入顺序回传 `{files:[…], failed:[…]}`，
  内部并发读；某个路径读不到只会出现在 `failed` 里，不影响其余文件。
  **相互独立的取证一律用它**：读文件本身是毫秒级，但每多一轮就多一次
  秒级的模型往返、还要重传整个对话历史——串行读的代价几乎全在等模型。
  只有「下一个读什么取决于这次读到了什么」时才分轮。
- 返回值里的 `tag` 是该文件的**内容快照标识**：接下来用 `edit` 改这个文件时把它带上
  （`{"path": ..., "tag": "<刚拿到的 tag>", "ops": [...]}`），文件若已被他人改动，
  `edit` 会拒绝而不是按你的旧行号改错地方。
</instruction>

<critical>
- footer 会列出被折叠的行范围——要看细节就**只重读需要的那几段**，不要一上来 `:raw` 拉整个大文件/长文档。
- 摘要/大纲只对够大的代码/带标题文档生效；解析失败、文件小、或散文无标题会自动回退整文件，无需担心。
- 要精确匹配某个符号名/调用点，用 `code_graph`（带 `name` 过滤）比整文件摘要更聚焦。

## 读完大纲后的精读纪律（省 token 硬规则）

拿到大纲/摘要后**不要把它切成几段又整篇回读**——那等于大纲白读、全文照拖。

- 只精读**与当前任务直接相关**的小节，按大纲里的行号点读（`path:start-end`）。
- **总量红线**：单个文件的按需精读累计行数**不应超过全文的 ~40%**。真要通读全文，直接一次 `path:raw` 并说明理由，别用"大纲 + 三段行范围"变相拉全文。
- **不要重复读同一文件**：读之前先把需要的行范围一次性规划好、合并成尽量少的调用（同一文件的多段可以放进同一个 `paths` 数组）；避免"读一点 → 想想 → 再回头读同一文件另一段"的往返。
- 已经读过的段落不要再读第二遍——需要回顾就用上下文里已有的内容。
</critical>
